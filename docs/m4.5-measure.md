# M4.5 の測定：discard・sticks・win の変換

`packages/fit` で、ランタイムが描画した波形を層に変換し直し、元と比べた結果（実装計画 M4.5 の 5 番）。
表は `npm run measure -w @sfx-atelier/fit` で出る（Chromium の OfflineAudioContext で描画、48kHz、乱数の種 3）。

## 条件

- 元の音：M2 のバンク `bank/mahjong.sfxbank.json` の `discard`・`sticks`・`win`
- 残響（`send`）を外した乾いた音で比べる。変換後の score にも、使うときに元と同じ `send` を付ける想定
- 変換の設定：STFT 1024 点・間隔 128 点、帯域雑音は 12 帯域、予算は既定（縮めた JSON 3072 バイト、層 24）。層の上限 8・4 も並べた
- 距離：マルチ解像度（256〜2048 点）の対数スペクトルの差の平均（dB）。括弧の中は「同じ score を別の乱数（種 4）で鳴らしたときの差」で、雑音や揺らぎ（`variation`・`jitter`）があると、これより小さくはならない

## 分かったこと

1. **精度は足りている。** `discard` と `sticks` は、層の上限 8 以上で「別の乱数どうし」と同じくらいの差に収まる。`win`（雑音なし）は 1.4dB。山・立ち上がり・長さの差も小さい
2. **合成で書いた 16 音は、変換しても小さくならない**（提案書 6.5 の予想どおり）。元が数個の層で書けているため、gzip 後で 50〜100 バイトほど増える。層の上限を 4 にすると元より小さくなるが、`sticks`・`win` は差が大きくなる。合成の音には使わず、**録音（M5c の物理エンジンの録音・読み込んだ wav）を JSON にするときに使う**のがよい
3. **プロニー法（B）は今は要らない。** 30ms 前後で消える成分（`discard` の 2730Hz、d = 0.028）も、窓が始まりより後ろのフレームだけで直線を当てはめれば ±10% に入った。必要が出るまで後回しにする（計画の 6 番）

## 今の限り

- 同じ高さの音符を続けて鳴らす音（`kan` のように tune が 50 セント程度しか違わない連打）は、成分が 1 本につながり、2 つ目以降の音符の成分が別に出ない
- 雑音は 12 帯域の固定。帯域雑音を 2 つで書いた音も、周りの帯域に分かれて 5〜10 層になる（層の上限で寄与の小さいものから外れる）
- 揺らぎ（`variation`・`jitter`）は戻さない（1 回分の波形からは分からない）
- 残響を含んだ波形は、残響の尾も減衰として当てはめる（乾いた音を渡す方がよい）
